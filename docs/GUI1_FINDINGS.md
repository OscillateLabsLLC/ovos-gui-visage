## Process

We do not work around a spec problem. When code and spec disagree, open the spec PR to `OpenVoiceOS/architecture`
(`dev`) on the same day, and make the code follow the proposed text. If the PR is rejected, the code follows the spec
and the row records the outcome. Add one row per finding, newest last. "Spec says" quotes or cites the clause with a
line range. "We found" cites evidence: a file and line, a test or a fixture. "Outcome" is `open`, `merged`, `rejected`
or `superseded by Fn`. A finding about OVOS code that the spec already covers is not a spec finding: it goes to that
repo as an issue or a PR, and it gets a row here only for traceability.
