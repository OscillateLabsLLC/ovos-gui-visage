## Process

We do not work around a spec problem. When code and spec disagree, open the spec PR to `OpenVoiceOS/architecture`
(`dev`) on the same day, and make the code follow the proposed text. If the PR is rejected, the code follows the spec
and the row records the outcome. Add one row per finding, newest last. "Spec says" quotes or cites the clause with a
line range. "We found" cites evidence: a file and line, a test or a fixture. "Outcome" is one of:

- `open`: nothing upstream has settled it.
- `merged` or `rejected`: the upstream PR's result.
- `superseded by Fn`, or `superseded by amendment X`: a later finding, or a drafted amendment that Visage already
  follows, replaces this row's rule.
- `fixed`: a code finding fixed in the repo named in the row (Visage, or WIRE.md), with the test that proves it.
- `withdrawn`: the finding was wrong; the row says why.

"Upstream PR" names the PR once it exists. Until then it names the local amendment branch in the gui1-upstream
architecture clone (`gui1/<name>`, summarised in gui1-upstream `SPEC_PROPOSALS.md`) that answers the finding. Where that
draft differs from the row's proposal, the "Proposed change" cell ends with one line that starts "Draft:".

A finding about OVOS code that the spec already covers is not a spec finding: it goes to that repo as an issue or a PR,
and it gets a row here only for traceability.
